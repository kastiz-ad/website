# KASTIZ ONE — Enterprise Edition Report

Version: `20260730-enterprise-edition-v1`

## Outcome

Enterprise Edition has been implemented as a reusable organization foundation layer. It expands ONE beyond individual accounts while preserving the existing Mission Engine, Provider Layer, Approval Engine, and approval-first architecture.

This milestone does not redesign the public UI and does not claim live SSO, live HRIS, live expense, or live corporate travel integrations.

## Architecture

New module:

- `js/engine/enterprise/enterprise-edition.js`

The Enterprise layer models:

- organizations;
- members;
- roles;
- permissions;
- departments;
- projects;
- budgets;
- corporate policies;
- approval chains;
- reporting;
- audit logs;
- organization isolation;
- SSO preparation.

The layer is intentionally business-logic-light. It prepares structured enterprise context that existing and future Mission Engines can consume.

- Companies
- Teams

- Travel management groups

- Government organizations

## Permissions

Enterprise roles are mapped to explicit permissions instead of informal access:

- Owner
- Administrator
- Manager
- Executive Assistant
- Traveler
- Finance
- Auditor
- Guest

Permission areas include:

- organization management;
- member invitation and management;
- department and project management;
- mission and travel request preparation;
- manager review;
- finance review;
- final approval;
- budget visibility and management;
- corporate policy management;
- reporting;
- audit review;
- SSO configuration preparation.

Guests are intentionally restricted. Travelers cannot approve their own enterprise execution chain unless separately granted a higher role.

## Approval workflow

The Enterprise approval chain follows the requested flow:

1. Employee creates a trip request.
2. Manager reviews.
3. Finance reviews.
4. ONE prepares the reservation package.
5. Final approver reviews.
6. ONE marks execution ready.

The chain enforces ordered progression. Steps cannot be skipped. Permission checks are applied before every human approval.

## Corporate policies

The policy evaluator supports:

- preferred airlines;
- preferred hotels;
- maximum travel budget;
- meal limits;
- cabin restrictions;
- compliance rules.

Policy results separate:

- blocking violations;
- non-blocking warnings.

This prevents ONE from falsely claiming a request is compliant when it exceeds policy.

## Reports

The Enterprise reporting object supports:

- total travel spend;
- department spend;
- upcoming trips;
- estimated savings generated by ONE;
- approval history;
- approval status summary.

Reports are scoped to the organization ID and isolation key.

## Security

Implemented safeguards:

- organization isolation key: `org:{organizationId}`;
- cross-organization access checks;
- explicit role-permission matrix;
- audit events for organization creation, member changes, department/project creation, policy updates, and approval decisions;
- SSO status remains `setup_required` unless real authentication is configured and verified.

No SSO provider is presented as connected by this milestone.

## SSO preparation

The SSO preparation object supports future SAML/OIDC setup and clearly labels:

- provider type;
- required metadata;
- callback URL;
- domain verification requirement;
- founder/admin action required;
- live: `false`.

## Enterprise roadmap

Recommended next steps:

1. Add an admin UI for organization settings after founder approval.
2. Connect SAML/OIDC SSO providers using secure environment variables.
3. Add SCIM provisioning after SSO is working.
4. Connect expense, HRIS, corporate travel, and procurement providers through the Provider Marketplace SDK.
5. Add region-specific compliance packs.
6. Add enterprise billing and invoice reporting after finance provider credentials exist.

## Production readiness note

This is a production-oriented foundation, not a complete enterprise product. It is ready for integration into the existing ONE architecture, but live enterprise deployment still requires:

- real authentication provider configuration;
- SSO metadata and domain verification;
- organization admin UI;
- persistence layer connection;
- enterprise-specific privacy and legal review;
- live provider integrations where relevant.
