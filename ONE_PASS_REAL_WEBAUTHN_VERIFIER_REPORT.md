## Verifier implementation

- `functions/api/v1/_lib/passkeys.js` now imports SimpleWebAuthn server functions directly.
- Registration verification uses `verifyRegistrationResponse`.
- Authentication verification uses `verifyAuthenticationResponse` with the stored credential public key and counter.
- Environment strings no longer act as verifier proof.
- Test verifier injection remains possible only through internal construction with `allowInjectedVerifier: true`; the API route does not expose this through HTTP.

## Registration behavior

- Server generates a challenge.
- Server stores the challenge with purpose, action hash where relevant, RP ID, expected origins, expiration, and single-use state.
- Registration options are generated by `generateRegistrationOptions`.
- Verification checks challenge, expected origin, expected RP ID, user presence, and user verification.
- Verified credential ID, public key, sign count, transports, device type, backup state, AAGUID, origin, and RP ID are prepared for storage.
- Duplicate credentials are rejected.

## Authentication and sensitive-action behavior

- Authentication options are generated by `generateAuthenticationOptions`.
- Authentication verification loads the credential by authenticated user and credential ID before verifying the signature.
- Revoked or cross-user credentials are rejected.
- Sensitive actions require exact purpose/action/resource hash and a single-use consumed confirmation.
- Non-multi-device counter rollback is treated as clone risk.
- Multi-device/backed-up passkeys are handled without assuming monotonic counters always advance.

## RP and origin configuration

- `WEBAUTHN_RP_ID` is explicit.
- `WEBAUTHN_RP_NAME` is explicit.
- `WEBAUTHN_EXPECTED_ORIGINS` supports an explicit allowlist.
- Wildcard origins are rejected.
- Malformed origins are rejected.
- Production rejects localhost and non-HTTPS origins.
- Development allows localhost HTTP only.
